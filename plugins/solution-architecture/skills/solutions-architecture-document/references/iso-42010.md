# ISO/IEC/IEEE 42010:2022 (SAD well-formedness)

Paywalled. Point at the [ISO catalogue](https://www.iso.org/standard/74393.html)
and the [IEEE store](https://standards.ieee.org/). Do not invent clause letters.

This SAD must satisfy these well-formedness checks (plain language, not a
clause dump):

1. **Stakeholders and concerns.** The stakeholder table names each
   stakeholder **and** at least one concern they hold. A role with no
   concern is incomplete.
2. **Viewpoints.** Each architecture view (4a–4f, plus Overview and
   Management as views if they carry structure) satisfies a named
   viewpoint: what questions that view answers, for whom.
3. **Correspondences / inconsistencies.** Where two views talk about the
   same element (auth, tenant, deploy target), say they agree or name the
   inconsistency. Do not leave a silent contradiction.
4. **Decisions and rationale.** ADRs already carry decision + rationale.
   Every Key Architecture Decision in Section 1 has an ADR.

Do not import a full TOGAF ADM. That cycle is context-only.
