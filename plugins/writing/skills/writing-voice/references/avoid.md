## Sentence habits

- The dunk: `X is not Y` / `it's X, not Y` / `Not X, but Y.` No exceptions.
- "Isn't just X, it's Y."
- The couplet: a short rule, then a second sentence that explains, restates, threatens a future, or scores the mistake.
- If the first sentence still needs a second sentence to make sense, make the first sentence specific.
- A semicolon may join two closely related independent clauses that are both actions or both conditions; it must not smuggle a gloss.
- The three-adjective pile ("clear, concise, and compelling").
- "X plays a role in shaping Y."
- A closer made of three short fragments. Write a complete sentence.
- Restating the heading as the first sentence under it.
- A skill YAML `description` that is a slogan, a keyword dump, or a Hard rule copied into the trigger. Write when to use the skill.
- Saying the same fact twice.
- Decorative ensures / highlights / supports / reflects when a concrete verb would do.
- Intensifiers with no number: significantly, effectively, crucial, vital, essential, increasingly.
- Punchy fragments for drama ("Not a detail. A design decision.").
- Building to a turn of phrase. State the claim, then stop.
- False-balance closers: "it depends," "while this may vary," "many people feel."
- Copula dodging: "serves as," "stands as," "functions as" when you mean "is."
- Replacing a banned construction with a new slogan ("fails the bar" for "it's X, not Y"). Say the concrete problem.
- A slogan under the title. If the first Hard rule already says it, go from the title to Files or Rules.
- courtroom `evidence` as a noun for why. Say why, using the code, a test, or the API contract.
- `Ask:` as a label. Write `Ask if`.
- `without waiting` / `no wait`. Write `go ahead and add it`.
- `name the` as a verb of labelling. Write `which clarifies the rule`, `Write down the command you ran`, or `Write down how you reproduced it`.
- `conservative` for a small change. Write `minimal`.
- `style nit` / `nits` / `mints`. Write comments about formatting or naming.
- `carve-out`. Write `exception`.
- `cannot state`. Write `do not already make clear` or `do not cover`.
- `disposition`. Write `pick one: fix it, reject it, or ask if you need more`.
- Heading `Quality bar`. Write `Quality standards`.
- `with a name` as a decorative tack-on, including "with a name on each row," "and names each row," and "give each row a name"; if the sentence already said the cases go through one test, stop and leave row names out.
- `table` as the unnamed grid of cases, including "one table," "in one table," "stop at the table," "with a name on each row," "and names each row," and "give each row a name"; if you mean many cases of one behavior in a single test, say that, and leave table for a database table, an HTML table, or a documented table the sentence already named.
- `stay silent` for "they did not answer" or "no answer given".
- A leftover closer of about 3-4 words that states a spare fact ("Deployment only if asked."); put the fact in the sentence that needed it, or leave it out.

## Also don't

- Short sentences that only reinforce and add no information.
- ":" for anything that is not a title. Prefer ";" if needed.
- Over-explanation. The reader is not an idiot. Avoid "Two things and only these two."
- Stating what you are not doing, or decisions not made.
- Enthusiasm inflation ("great question," "exciting," "amazing").
- Hedged recommendations. Pick one and say why.
- Blending an elevated in-fiction voice into rules text or vice versa.
- Over-formatting. No bold. No heavy markdown. Plain headings and short paragraphs.
- Reproducing typos. The voice is direct, not sloppy.
- Unspaced em dashes. Asides use parentheses or a spaced en dash ( – ).
